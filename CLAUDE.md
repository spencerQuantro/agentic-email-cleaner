# CLAUDE.md

Sweep: a self-hosted, Claude-powered Gmail cleaner. pnpm monorepo, Node 22.

## Layout

- `packages/shared` — zod schemas (the API contract), `decide()` policy, demo fixtures. Shipped as TS source; no build step.
- `apps/server` — Hono API (`src/app.ts`), run engine (`src/engine/`), stores (`src/store/`: `MemoryStore` for demo/tests, `DbStore` for SQLite via libSQL + Drizzle).
- `apps/web` — React + Vite + Tailwind v4 + TanStack Router/Query. File-based routes in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin (regenerate with `pnpm --filter @sweep/web build`).
- `docs/designs/*.dc.html` + `docs/HANDOFF.md` — the visual source of truth for the UI.

## Commands

- `pnpm dev:demo` — run everything on fixtures (no Gmail or API key needed)
- `pnpm test`, `pnpm typecheck`, `pnpm build` — run all three before committing
- `pnpm db:generate` — after any change to `apps/server/src/db/schema.ts`; commit the generated migration

## Rules

- **Safety invariants. Never break these:**
  - Deletes move mail to Gmail Trash (`messages.trash`); never call a permanent delete.
  - The confidence threshold is enforced in `decide()` (plain code), never in a prompt.
  - Only headers, subjects and short snippets go to Claude, never full message bodies.
  - Dry-run mode must not call any mutating Gmail method or unsubscribe endpoint.
- All API responses are validated on the client with the shared zod schemas (`apps/web/src/lib/api.ts`). Add new endpoints to `packages/shared` first.
- UI: match `docs/designs` exactly; use the theme tokens in `apps/web/src/styles.css` (e.g. `bg-review-bg`), not raw hex. Real `<button>`/`<a>`/`<label>` elements, 44px minimum touch targets, visible focus ring.
- Tests use fakes (`apps/server/src/test/fakes.ts`, MSW in `apps/web/src/test/server.ts`); never hit real Gmail or Anthropic in tests.
